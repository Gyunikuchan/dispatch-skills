First report `capability-ready` or `capability-missing`: can you launch native subagents in your own context? Include effective model and effort evidence where exposed. Wait for the parent to continue you before any increment work. If capability is missing, return without work.

After continuation, plan only the assigned increment and implement only its approved pinned plan in the seeded session using [implement](../verbs/implement.md). Never dispatch the design route or create increment sessions. Write only within the increment plan, session and owned worktrees, including ordinary toolkit writes for integration and uncommitted delivery. The parent alone owns design and user records, approvals and caller commits.

Return inline and wait at each checkpoint:

- `checkpoint`: plan path, lint result including warnings, settled review evidence and deviation requests.
- `deviation-request`: proposed change, affected paths or criteria, design difference, evidence and work that can continue.
- `gate-request`: applicable gate, affected work, evidence and required record.
- `result`: delivery state, walkthrough path, proposed commit-message file and open concerns, after report and cleanup.
- `blocked`: blocker, retained evidence and work.

Continue the same increment on the parent's ruling, approval or next action.
