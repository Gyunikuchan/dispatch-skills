# Write-subagent brief (shared frame)

Assembled with `write-brief-task.md` or `write-brief-hotfix.md` by `domain/prompt.ts`.
`qualityBar(consumer)` fills the quality slot for both task and hotfix writer stages.
Structured `envelope`, `selfCheck`, `packet`, `manifest`, `boundaries`, `criteria`, and
`admissionDefects` remain generated by the driver.

## Prompt template

- `<Expected Envelope Path>` — exact output file for this write action.
- `<Self Check Command>` — command that validates that file.
- `<Checkpoint Command>` — task block only: command that records RED test contents.

````markdown
### Outcome handoff
- Write the complete implementation-outcome JSON to `<Expected Envelope Path>`.
- After launch, copy the task's exact attempt, signature, and assigned handle from the `Await write` frame into its generated self-check event, then run `<Self Check Command>`; correct every listed defect before returning.
- List each changed file in `files` with one short clause on what changed there.
- In chat, return only the status, one-line summary, concerns, and envelope path. Keep evidence rows in the JSON file.

<<slot:purpose>>

### Quality and conventions
Read `AGENTS.md`, including nested ones on the paths you edit.
When Governing spec is present, read the whole spec it names before the bounded plan range. Use its Path and Hash as the governing identity.
<<slot:quality>>

### Verification and editing
- Put agent-created helpers, captured logs, intermediate data, and backups in `<run>/scratch/<envelope-dir-name>/`. Derive `<run>` from `<Expected Envelope Path>` (`<run>/<envelope-dir-name>/outcome.json`); copy its parent directory name exactly, without reconstructing an effect id. Create working directories only when needed. Classify backups by purpose even when named like deliverables. Keep the outcome envelope and driver-owned evidence at supplied paths and production edits within the brief's scoped repository paths.
- Verify with your mapped `commands` only; after each change, rerun just the commands it affects. Never run the repository's aggregate test suite: the driver runs every gate after you return.
- Edit with your file edit/write tools, batching related changes; do not chain shell text rewrites (sed, awk, python) over source files.

<<slot:kind-rules>>

### Scope requests
- Edit only inside the current brief. When required work exceeds it, follow the request rule in your kind rules before editing outside it.
````
