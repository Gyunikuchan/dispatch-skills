# Implement

Resolve the full governing spec and plan, following Parent pins through a design when present. For an objective, author the spec and plan first. For a design, deliver its ordered increments. The [toolkit contract](../toolkit.md) owns tool arguments and result shapes.

1. Lint the artifacts. Resolve outstanding plan findings, failed slots and escalations. Run a new plan review only when no completed plan review in the session covers the current spec and plan hashes, or when the user asks; a settled plan from `plan` is not re-reviewed. Bind spec, plan and optional design in the ledger; record the chosen level and applicable user approval tuple.
2. Run baseline checks and retain failures. Choose bounded repairs or reported limitations against governing intent.
3. Create each ready task worktree, render its brief and launch a native writer there. Honor prerequisite ordering and configured native capacity. A brief carries the whole spec, shared plan context, task scope, criteria and checks.
4. Keep each writer running through inspection, discriminating RED tests, implementation to GREEN, cleanup and affected-file verification. Writers edit only assigned paths and run no Git write commands. Their result report names changed behavior, checks, concerns and artifacts. Missing RED is a review finding.
5. Inspect the actual delta and evidence. Submit the candidate with the worktree tool, integrate it and run criterion and contract verification on the integrated tree. A submitted candidate alone does not release prerequisites; verified integration does.
6. Review code and judge the durable or FINAL coverage named by each transient criterion's Covered by against the quality bar. A green suite cannot detect missing protection. Resolve every MUST: reject with evidence or settle a valid duplicate; unruled and deferred MUST findings block pruning. Apply accepted fixes in integration, commit and rerun criterion and contract checks. Re-review until a completed full review covers the exact integration HEAD, with no failed slots, open escalations or unresolved accepted fixes. Any later source edit needs checks and fresh review. The no-fix path reuses the exact completed review. For transient plans, call the prune tool, then run final verification as defined in [toolkit lifecycle](../toolkit.md#worktree-prune). Preserve pre-prune RED/GREEN evidence and source commits. Deliver the exact verified source as unstaged caller changes (no caller commit) only after final checks pass; complete the report and clean owned worktrees. Follow [delivery preconditions and recovery](../toolkit.md#worktree-deliver) for a dirty caller or interrupted delivery. For failures or interruption, retain the pruning records and work and follow its recovery rules.

Treat scope overrun, concerns, conflicts and red baselines as information with options. Verify each claim, then repair, clarify the plan, retry, retain for recovery or escalate a material user decision. Tool refusals identify an operation prerequisite; inspect the result rather than inventing success or bypassing it. Waivers and manual completion require user quotes.

Edit living plans and designs in place under their phase rules. Notify only writers whose paths or criteria change, with current scope, rationale, changed criteria, evidence and next action; keep their handles and completed work. Continue independent writers. Intent edits follow [spec operation](../spec-stage.md#revision-protocol).

For conflicts, inspect both tasks' intent and resolve within their paths in the integration worktree, then continue integration. Discarding work follows the [user gate](../decision-frame.md#user-gate-boundaries). Record unresolved conflicts and retained candidates.

After interruption, use status, inspect recorded launches and integration state, and reconcile live handles before relaunching. A relaunch acknowledges the old writer as stopped; do not run two writers against one worktree. Verification must follow the last relevant edit. Report completion only when criterion evidence is current, required reviews are resolved, and delivery and cleanup are accounted for.
