# Review

Every review uses a supplied or reused governing spec, or authors one through [spec operation](../spec-stage.md#resolve-and-author). Resolve artifact Parent pins transitively; otherwise reuse the session spec or author from full chat and the diff, labeling inferred requirements `(inferred)` and recording user decisions only with evidence. All reviewers read the whole settled spec. The spec is the intent channel; use [intent-first rulings](../review-rules.md#intent-and-findings) and the [revision protocol](../spec-stage.md#revision-protocol) when an answer changes intent. Standalone code review settlement adds no spec-approval gate.

Use `start review --session-dir <dir> --orchestrator <platform> [--kind code|plan|design] [--spec <path>] -- <target>`. Empty code target selects working-tree changes; a revision/range selects a diff, artifact extensions infer their kind. Explicit `--kind` wins. Pass `--spec` to name the governing intent; review prompts carry its settled path and hash. Read [review rules](../review-rules.md) before adjudicating claims or applying clusters. A code review of planned work attaches the plan, whose `## Key Decisions & Context` entries are settled decisions; rule a finding that contradicts one as an intent finding under [intent-first rulings](../review-rules.md#intent-and-findings). Follow [the contract](../..) through rule, fix, and decision boundaries.
