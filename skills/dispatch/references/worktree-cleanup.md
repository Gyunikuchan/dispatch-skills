# Worktree cleanup

After successful `report complete`, run `worktree cleanup`. Read its result file before handoff. `removed` lists removed paths; `kept` rows include `path` and `reason`, and may include changed `paths`, an error `code`, a bounded `message`, or a session-relative `recoveryPath`. A path can appear in both lists when its directory was removed but Git registration, pruning or ref release failed.

An operational cleanup failure returns `ok: false`, exit 2 and reason `cleanup-incomplete`. Its `value` still contains all known `removed` and `kept` rows; exit 2 does not undo completed work. Read the value and report every retained owned path. A successful result may also contain `kept` rows for unowned, non-terminal or unpreserved paths; these are not always operational failures, but they still need a recovery or retention decision before a successful handoff. A refusal before per-path cleanup returns its own reason and message, not the structured partial cleanup value.

Tools track owned writer and integration paths in the ledger under `.state/worktrees/`. Cleanup checks physical containment, ownership, terminal state and preserved snapshots before removal. It compares integration history with the recorded delivery source, which the caller never receives as a commit. Merged worktrees need no restoration: cleanup removes integrated writer worktrees and an integration worktree whose HEAD is the delivered source, with any edits or ignored files. It also removes an owned, contained directory that Git already deregistered and has no `.git` link, such as an interrupted removal leaves, when the ledger shows it merged; otherwise it keeps the directory as unpreserved. Removal unlinks junctions and symlinks without following them. For other terminal worktrees, cleanup retains unpreserved worktree or index edits and ignored files. See [delivery recovery](toolkit.md#worktree-deliver).

Cleanup releases a writer candidate ref only when that writer is integrated and its path has no retained result row. It keeps candidate refs for unintegrated or retained writers. It keeps the integration branch while any owned path is retained; after successful cleanup it may delete that branch only when it still points to the recorded delivery source. The delivered-source ref is always retained.

Before cleanup, confirm that agents using the paths have stopped. For host-managed worktrees created outside the toolkit, record ownership and use the host lifecycle to archive them after preserving work. Verify removal with host artifacts or Git's worktree list. Cleanup does not stop unrelated processes or services, and an external process can still hold a path.

After `cleanup-incomplete`, keep the session and recovery refs. Resolve the reported blocker, inspect the path and Git registration, then retry. Removal retries are bounded; cleanup cannot release an external lock. Each retry checks preservation again. If partial deletion leaves preserved unmerged work that no longer matches its snapshot, cleanup retains the remnant and recovery ref. Report the needed recovery; do not infer which missing files cleanup deleted. No deletion journal or backup makes this retry automatic.

A failed rename preflight can strand a directory at the deterministic sibling `.<worktree>.cleanup-recovery`. Read `kept.recoveryPath`; a missing recorded path does not prove removal. On retry, cleanup restores this sibling only after checking physical containment, a regular directory, matching Git registration/control metadata and a readable HEAD, with no conflicting original path. It then repeats normal preservation checks before removal. An occupied, conflicting or unverifiable sibling remains retained. Do not delete or move it manually to bypass these checks.

For retained paths, inspect and report the reason. Resolve owned retained paths before a successful handoff, or record an explicit user retention decision. Preserve the session, result files and required evidence. Cleanup never implies that failed verification passed.
