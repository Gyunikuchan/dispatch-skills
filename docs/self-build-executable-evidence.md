# Self-build executable evidence

The operational owner is [self-build](../skills/dispatch/references/self-build.md). This inventory records each executable fence and its write boundary. Test names refer to `tests/e2e/self-build-preparation.test.ts` under the parent `documented preparation rejects unsafe ownership and linked paths`, unless stated otherwise. Each subtest uses a separate disposable repository and initialized session.

The materializer test harness tries the new four-argument entry first. For baseline regression replay only, an `Unknown helper` response retries the original documented three-argument entry unchanged. This makes the old unsafe writes observable instead of treating its argument rejection as proof of safety. The production entry accepts only the current layout.

The entry also covers fresh session initialization without fixture-created `.state`: `fresh initialized repository completes materialization capture and verification` and `fresh initialized worktree completes materialization capture and verification` run all three preparation stages. The worktree has a real Git `.git` file. `invalid git marker grants no helper write authority` replaces the repository metadata with an empty `.git` directory and proves scratch is absent after refusal. Git resolves the target's top-level identity before the first helper write; a missing `.state` is created only after the read-only checks pass, while an existing `.state` must be a real directory.

The trust boundary remains pre-existing paths in a local workspace. These checks do not claim protection against hostile concurrent replacement of filesystem ancestors. This inventory adds no operational policy; recovery and lifecycle decisions remain in the reference.
