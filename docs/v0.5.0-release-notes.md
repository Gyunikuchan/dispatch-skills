# v0.5.0 release notes

v0.5.0 replaces the companion workflow contracts with one model-visible `dispatch` contract and a script-driven action loop. Existing slash-command names remain as user-invoked aliases. The runner and driver preserve read-only provider isolation, evidence-based rulings, approval-gated production writes, consensus, recovery, and technical-design increments.

## Breaking changes

- Use `/dispatch [level] [(pins)] [ask|plan|design|review|implement]: <argument>` for automation.
- `dispatch-plan-review`, `dispatch-code-review`, `dispatch-design-review`, and `implement-dispatch` only translate user arguments; they require `dispatch` in the same installation scope.
- Standalone review is report-only unless the user explicitly supplies `--fix`. The code-review alias never adds it.
- One `skills/dispatch/config[.local].jsonc` replaces both v0.4 configs. Old schemas fail with a migration diagnostic; files are not migrated automatically.
- `dispatch.mjs --help` is authoritative for flags. Documentation intentionally carries no duplicate flag table.
- Legacy artifact decisions and the `ACTIONABLE` resolution status are unsupported.
- The OpenCode runner requires opencode CLI v2; v1 is no longer supported. Argv drops `--pure`
  and `--variant` entirely (no version detection, no fallback); reasoning effort now folds into
  the model as `model#effort`. Config reads move to v2 keys: `providers.<name>` (`settings.baseURL`,
  `settings.apiKey`) and `providers.<name>.models.<model>.settings.reasoningEffort`. Users on
  opencode v1 lose the opencode delegate until they upgrade.

## Configuration field map

| v0.4 field/location | v0.5 field/location | Notes |
|---|---|---|
| dispatch `platforms` | `read-delegates` | One provider candidate table for ask and every review. |
| implement `plan-review` | `phases.plan-review` | Policy only. |
| implement `code-review` | `phases.code-review` | Policy only. |
| plan policy reused for design | `phases.design-review` | Design policy is explicit. |
| `targetCount` | `targets` | Number or `"all"`. |
| `maxRounds` | `rounds` | `0` disables the phase. |
| `consensus` | `consensus` | Now nested under the phase and level. |
| phase `platforms` | phase `only` + `read-delegates` | `only` filters membership; models live in the candidate table. |
| `implementation.platforms` | `write-subagents` | Native host write-subagent fields. |
| `implement-dispatch/config*.jsonc` | removed | Copy and edit `dispatch/config.sample.jsonc`. |

Level overrides live inline on candidate entries. Exact level wins, then nearest lower, then lowest higher. Per-phase model selection is intentionally removed.

## Alias compatibility

```text
/dispatch-plan-review high (all): plan.md
→ /dispatch high (all) review plan: plan.md

/dispatch-code-review --fix: main..HEAD
→ /dispatch review code --fix: main..HEAD

/dispatch-design-review: design.md
→ /dispatch review design: design.md

/implement-dispatch high (agy): requirement
→ /dispatch high (agy) implement: requirement
```

Without explicit `--fix`, every review mapping remains report-only. Missing `dispatch` stops with an alias-specific diagnostic.

## Decision record (D1–D22)

1. **One skill:** merge operational assets into `dispatch` to remove duplicate contracts.
2. **Script-driven workflow:** deterministic driver actions replace prose choreography.
3. **No legacy compatibility:** reject old configs and artifacts clearly instead of maintaining dual paths.
4. **Consensus retained:** disputed high-severity rulings return to their effective sources when enabled.
5. **Technical designs retained:** design and increment execution load only for that branch.
6. **Aliases replace competing triggers:** familiar commands remain user-invoked; `dispatch` is model-visible.
7. **Review fixes opt in:** standalone review is safe and report-only by default.
8. **Phase and increment stay distinct:** phases describe execution; increments describe design scope.
9. **No size gate:** measure contract load without blocking legitimate detail.
10. **No output truncation:** action payloads include every finding or cluster the host must judge.
11. **Ask accepts level without pins:** level consistently selects the candidate tier.
12. **Terminology is checked:** shipped contracts and templates reject glossary-banned synonyms.
13. **Five levels remain:** sparse config resolution keeps them inexpensive.
14. **Two candidate tables:** read delegates and write subagents define models once; phases hold policy.
15. **Resume runs forward:** `--phases` accepts only `from:<phase>` to preserve gates.
16. **Driver output measured:** efficiency is compared empirically rather than assumed.
17. **Conditional guidance travels with actions:** branch rules load when needed.
18. **Shared prompt frame:** common delegate framing is merged while kind rubrics remain distinct.
19. **Phases are independent entries:** canonical artifacts, not in-memory output, supply inputs.
20. **First review settlement:** strengthened protocol, terminology, and migration coverage.
21. **Second review settlement:** clarified grammar, inference, level raising, and phase behavior.
22. **Third review settlement:** fixed prefix diagnostics, plan resume, ledger timing, and approval recovery.

The `design` run exposed a script defect: in `skills/dispatch/scripts/driver/index.mjs`, `next()` returned `advanceDesign(state, checked.value)` without persisting the new pending action via `save()`, so a `--run design` run never saved `pending`/`reviewState` after its first action; the subsequent `launch` reply was then rejected against the stale `author` schema. Fixed here by routing the design branch through the same `save()` used by the other advance paths; a regression test (`tests/skills/dispatch/driver-design-save.test.mjs`) starts `--run design`, replies to `author` with a valid design, and asserts the persisted state file's pending action matches the emitted `launch` rather than staying `author`.

Two earlier full-implement attempts ended at the RED gate with `stable-failure`: the tests-only delegate claimed a RED identity that did not match the host's. The gate behaved correctly; a first-attempt identity mismatch is terminal (keep-for-repair/revert-attributable end the run; a new governed plan is required).

## Upgrade

1. Preserve a copy of v0.4 configs.
2. Copy `skills/dispatch/config.sample.jsonc` to the desired dispatch config filename.
3. Apply the field map and define an explicit `design-review` phase if needed.
4. Run `node skills/dispatch/scripts/dispatch.mjs --validate-only` and `--doctor --orchestrator <platform>`.
5. Update automation to call `dispatch`; user-facing aliases may remain.
