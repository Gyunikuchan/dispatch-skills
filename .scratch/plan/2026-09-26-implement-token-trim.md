# Implement-flow output-token trim

> **TL;DR:** Cut orchestrator and subagent output tokens in `/dispatch implement` without reducing orchestrator context.
> **Status:** Spec agreed 2026-09-26; not a lint-ready plan. Convert through `/dispatch plan` before implementing.
> **Origin:** Retrospective on run `bb936cef-…` (session `ed5f18e6-…`) plus follow-up review.

## Agreed changes

### A. JSON-only write-subagent replies
- **Problem:** Write subagents add a prose recap (~200 words) before their implementation-outcome envelope; it duplicates the envelope's `summary` and `evidence` rows, and the orchestrator then relays it.
- **Change:** The per-stage instruction in `skills/dispatch/scripts/driver/write.mjs` (`writeAction` instructions, ~L141–142) tells the subagent that its final message is the envelope only, plus any concerns inside the envelope.
- **Acceptance:** Tests assert the instruction text; a live run's hand-back contains no prose outside the envelope.

### B. Single-source Success Criteria
- **Problem:** `skills/dispatch/references/templates/plan.md` requires both a Success Criteria table and a per-criterion bullet list, so every verify command (the longest strings in a plan) is authored twice and the two copies can drift apart.
- **Change:** The planner writes only the per-criterion list. Either drop the table, since the driver already parses the list, or regenerate it with `plan/lint.mjs --fix` for human scanning. Pick one during planning; regeneration is preferred if people rely on the table.
- **Interface impact:** Breaking change to the plan template. Existing plans with a table must still lint, or lint must auto-migrate them.
- **Acceptance:** A plan without a hand-written table passes lint and drives successfully; a table that disagrees with the list is either impossible or flagged.

### C. Adjudication wording
- **Accepted findings:** The driver reuses the delegate's sanitized defect text, so the orchestrator writes only the resolution.
- **Rejected findings:** Keep the orchestrator's full reasoning, and make it explicit enough that the next round doesn't raise the finding again. No trimming.

### D. Envelope handoff by path
- **Problem:** The orchestrator retypes each write subagent's envelope into its `{"raw": ...}` reply to the driver. That costs ~1.5k output tokens per run and risks transcription errors.
- **Change:** The write brief gives the subagent a driver-chosen envelope path in the run's session directory; the subagent writes its envelope there, and the orchestrator replies with only that path (or with `rejected`). The driver reads the file, validates it with the existing envelope checks (`--check-envelope`), and binds it to the pending action so a stale or foreign file is rejected.
- **Orchestrator context:** The subagent's final message is its status, the envelope's one-line `summary`, any concerns, and the envelope path, with no evidence rows. After validating the file, the driver's next action echoes status, summary, and concerns, so the orchestrator stays informed through input tokens only. This refines A for the path-based flow.
- **Interface impact:** Breaking change to the delegate-write reply shape (`references/templates/schemas/driver/delegate-write.json` and the `writeAction` instruction in `driver/write.mjs`). `{"raw": ...}` is removed with no fallback; the path reply is the only way to hand back an envelope (the `rejected` reply stays for refused launches).
- **Acceptance:** A delegate-write step completes with a path-only reply; a missing, invalid, or stale envelope file is refused with a repairable error; the orchestrator's reply contains no envelope content.

## Rejected or withdrawn
- **One-line `--drive` summaries:** rejected. Input tokens are cheaper, and full relays keep the orchestrator from searching for context on its own.
- **Skip baseline verification:** withdrawn. The baseline runs only the plan's criterion commands, is cached by content (`driver/verification.mjs` `cachedBaseline`), and separates failures that already existed from new ones.
- **Merge tests-only and production briefs:** withdrawn. They already share `write-brief.md`, differ by ~50-word blocks, and are generated by the driver at no orchestrator output cost.
